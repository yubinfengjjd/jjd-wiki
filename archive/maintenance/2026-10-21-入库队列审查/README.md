# Wiki 入库队列审查与修复结果

日期：2026-10-21。正式库：`E:\research-wiki\知识库`。

## 结论

此前“等 agent 处理 4”来自两个来源图样加两个模板草稿的重复计数，并非四项独立制作任务。作者确认两个模板后，原 CLI 仍因来源保留 `pending_template` 列出两项；这是剩余工作判定的缺陷，不应通过强改来源 ready 或制作额外版式回放来清零。

两个模板已依据本轮明确确认，通过公开 `mark-ready` 命令标为 ready。修复部署后，正式服务、三处 CLI 与前端均为：待签核0，待确认0，待 agent 处理0。原两篇旧迁移笔记继续归档，既有三个 SHAP 模板保留，当前总计5个可用模板。没有新建重复模板或额外图样。

## 根因与修复

1. CLI `pending` 只读来源 raw status，未检查所选 panel 是否已由可用模板覆盖。现统一读取只读 `workflow`。
2. 前端把所有模板 draft 都放入 agent 栏；成功回放等待作者确认也被算成 agent 工作。现按实际下一步归类。
3. 来源与其模板同时计数、导航角标和图库摘要各用 raw status，无法反映工作交接。现 API、队列、导航共用后端判定，来源卡片和摘要显示派生模板进度。
4. 部分方法配图及正文还保留“尚待模板化”措辞。已改为当前进度或中性的“来源图样参考，执行时另查关联模板”，清除会误导后续 agent 重做的描述。

新增 `rwiki/workflow.py` 只读派生，不增加持久状态，不修改来源签核、模板确认或验证记录。规则同步到 Wiki 的 AGENTS.md、开发源及 `.agents`、`.codex`、`.claude` 三处 research-wiki 全局安装；三个安装各266个文件通过清单哈希核对，全部指向同一个正式库。变更前安装文件与旧前端包保留在本目录 `backup/`。

## 正确链路

| 条件 | 下一步责任 | 队列行为 |
|---|---|---|
| 来源或新版本待签核 | 作者 | 来源列入待签核 |
| 来源已签核，所选 panel 缺有效模板覆盖 | agent | 核查缺口、归档或关联，保留已完成部分 |
| 已有模板草稿，尚无完整成功回放 | agent | 继续已有模板；不把来源重复计数 |
| 草稿有成功回放记录及 PNG/PDF/SVG，预览对应回放 | 作者 | 模板列入待确认；不自动标 ready |
| 选定 panel 均由 ready 模板覆盖 | 无剩余模板制作动作 | 来源显示模板已就绪，退出待办 |
| 归档或删除关联模板造成覆盖缺失 | agent | 缺口重新出现；恢复可用模板后重算 |

来源 `status: pending_template` 仍保留，因为没有额外签核其可选 layout 回放；对应 `workflow.stage: complete` 表示模板制作已完成。两者含义分别保存。模板可独立 render、推荐，不依赖来源整体 ready。重复 ingest/刷新不新建待办记录，也不替作者推进确认。
