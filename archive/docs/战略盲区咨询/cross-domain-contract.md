# 跨领域契约与适配矩阵 v1.1

日期：2026-10-24。依据：session.md的D017，以及requirements.md的R13–R15。本文件是规划；列出某领域不代表该领域全部方法、数据格式和工具已经实现或验证。

## 1. 产品适用范围

科研Wiki面向生物信息学、深度学习、影像组学、计算机药物设计、网络药理毒理学、蛋白组学、代谢组学等课题，支持未来新增领域和跨领域组合。

统一的是课题复用过程：问题与证据→材料与前提→路线选择→具体方法/工具→结果与可视化→变更与恢复→经验入库。不同领域保留各自的研究假设、对象语义、数据形状、结果判断和验证方法。

同一课题可以有多种测量类型、多个分析范式。深度学习可以用于影像、组学或分子数据；分类与适配不应把它们变成互斥目录。

## 2. 通用内核、领域配置和实现适配

| 层 | 负责内容 | 验收重点 |
|---|---|---|
| 通用内核 | 身份/版本、观察与证据、问题/路线、任务/产物、授权/预算、实际依赖、运行与恢复、草稿回流 | 核心状态操作不要求cell_id、Seurat、注释、轨迹或某种固定论文顺序。 |
| 领域配置 | 特定任务的材料语义、条件前提、可观察阶段、诊断/结果检查、候选知识和配图关系 | 可组合、可版本化；每个判断有范围和依据，不把一个领域通则强加于其他领域。 |
| 实现适配 | 某个R/Python函数、脚本/外部程序或既有流程的原生输入/参数、最小依赖、结果提取 | 逐分支真实调用；未实现/不支持/未验证各自明确，不用同名字段冒充兼容。 |

领域配置是可复用知识的结构化入口。定义与依据保留在正式Wiki现有方法/流程/接口及其资产中，配置引用规范id；runtime.json继续唯一声明实现依赖。SKILL/references说明如何读取和使用，不能另存一份手工维护的“各领域当前可用方法表”。

不为放置配置而制造新分析方法；不存在适当规范页/来源时先保留课题候选与配置草稿，再按原入库八步决定如何整合。配置对代码解析器的注册与任何执行适配器都要审查，不能读到一段外部文字就下载或执行插件。

## 3. 通用状态里的最小概念

| 概念 | 示例 | 约束 |
|---|---|---|
| 研究实体及身份 | 受试者、样本、图像、ROI、分子、靶点、肽段、蛋白、代谢特征 | 类型/命名空间/身份关系显式；不是每项任务都必须有患者或细胞。 |
| 数据/模型/文件对象 | 表、矩阵、影像及掩膜、结构文件、谱图、模型权重、内存对象摘要 | 保留原生类型、格式/版本和路径/指纹；内核不要求转CSV。 |
| 分析单位与设计 | 每患者、每样本、每图像、每分子、每特征、每次模拟 | 相同列名不授予同等统计含义；实体与观测/重复层级分开。 |
| 已有能力与前提 | 有表达数据、有分组、有分割、有预测结果、有受体准备文件 | 每项记录满足/不满足/未知、证据、适用对象和数据版本。 |
| 实现与运行 | 函数、命令行程序、模型推理、既有工作流 | 原始语言与调用形式保留，Wiki不承担网页执行；不强制包装成R/Python函数。 |
| 结果与主张 | 估计值、预测、特征、姿态、网络边、模型、图或诊断 | 结果文件存在与结论成立是不同事实；明确来源、可支持范围和限制。 |

阶段是已有证据和任务前提的组合，不设全库统一的“质控→注释→恶性识别”枚举。一个无细胞对象的模型评价课题也应能完成状态登记、路线建议、变更与恢复。

## 4. 领域适配矩阵

以下为首轮必须检查的代表性上下文。每行是设计覆盖范围；具体字段按所选任务/分支声明为必需或可选，不能要求整个领域的所有任务都提供所有字段。

| 领域/场景 | 原生输入与需保留的上下文 | 阶段证据与候选路线的表达 | 变更/结果检查的代表点 |
|---|---|---|---|
| 生物信息学：单细胞、bulk转录组及其他组学任务 | 对象/矩阵/序列或结果表；物种、标识体系、assay与变换、样本设计和单位，按分支声明 | 按当前材料给出可做/缺材料/缺实现项；单细胞注释仅在该任务中使用，不作内核字段 | 样本/注释/矩阵或参考资源版本变化；明确描述性结果与样本层推断的范围。 |
| 深度学习/机器学习 | 数据及分组/划分、预处理与特征定义、模型结构或来源、权重、训练配置、预测与评价对象；任务可为训练/推理/评价/解释之一 | 明确“有预测”不代表本库已训练过模型；已固定权重可支持的下一步与重新训练前提分开 | 划分、预处理、权重、配置、评价版本的实际依赖；GPU/驱动与资源按实现需要声明，评价通过不授予训练能力。 |
| 影像组学/影像分析 | 影像与必要ROI/掩膜、病例对应、几何信息、提取参数、特征/标签表 | 可从已有特征表接建模，也可在具备工具和输入时接提取；不强制所有课题重跑影像预处理 | ROI、影像、重采样/离散化等实际配置变化影响哪些提取结果；特征已存在与提取可重现分开。 |
| 计算机药物设计 | 按任务使用SMILES/结构/化合物性质、受体/配体、准备结果、对接盒/配置或模拟轨迹 | QSAR、虚拟筛选、对接等任务分别声明前提；不把所有CADD任务都要求提供受体 | 结构/准备/参数/打分程序与资源的版本；输出姿态/分数等保留原生对象，不能只有汇总CSV而丢计算条件。 |
| 网络药理毒理学 | 化合物/暴露、靶点、疾病/表型、网络及关系证据；数据库版本、物种/标识映射和任务需要的条件 | 区分记录到的关联、计算预测和待验证假设；候选网络分析/富集/验证路线带来源与缺口 | 数据库/映射/筛选阈值改变时追踪依赖；毒理任务所需剂量/时间等是否存在按具体实现判断。 |
| 蛋白组学 | 原始/处理质谱资料、肽段/蛋白/修饰对象或丰度矩阵、样本与批次、识别/定量处理信息 | 肽段到蛋白、修饰到位点等粒度明确；已有定量结果可用于哪些分析须单独判断 | 标识、定量/聚合规则、过滤、标准化、缺失处理及资源变化留下依赖，不静默套用表达矩阵假设。 |
| 代谢组学 | 质谱/色谱或处理后表、m/z/保留时间特征、化合物注释/鉴定状态、强度与样本/批次信息 | 区分测得特征与已确认化合物，明确可执行分析和注释/材料缺口 | 峰表/注释/批次处理/数据库改变的影响；不能把未知峰直接认作已鉴定代谢物去解释下游结果。 |

矩阵用于约束设计，不能作为自动给所有课题安排分析的固定菜单。首次引入具体方法时仍需读原始方法/官方实现、核对前提和实际证据。

适配契约的参考依据：

- [nnU-Net数据格式文档](https://github.com/MIC-DKFZ/nnUNet/blob/master/documentation/dataset_format.md)明确区分影像、分割和元数据，并要求相应几何/通道条件；这里只据此证明原生对象契约的重要性，不将nnU-Net格式强加给全部深度学习任务。
- [scikit-learn官方数据泄漏说明](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)区分训练和测试数据在预处理/拟合中的角色；课题状态需保留这种用途与划分信息。
- [PyRadiomics参数文档](https://pyradiomics.readthedocs.io/en/latest/customization.html)说明影像类型、特征及预处理设置；这些条件属于相应实现的实际依赖。
- [AutoDock Vina官方示例](https://autodock-vina.readthedocs.io/en/latest/docking_basic.html)展示受体/配体准备、参数和结构输出；本设计因此容纳外部程序和原生结构对象。
- [HUPO-PSI mzTab项目](https://github.com/HUPO-PSI/mzTab)区分组学结果概览和更详细证据的链接，并提供蛋白组/代谢组相关格式；本库保留证据指针，不把结果摘要误作完整重现材料。

网络药理毒理学的具体数据库证据类型和各算法假设，在选定实现时继续按原始来源核查；本轮未完成该领域的方法综述，不预填“所有关系已可信”的结论。

## 5. 通用方法与跨领域组合

方法家族以研究问题、估计目标、输入语义、单位和算法假设判定，不能按“属于哪个领域”重复建库。分类/回归、评价、解释、聚类、富集、网络等共用目的，仍需比较具体假设与实现差异；不能仅因都输出p值或特征表而强合并。

组合示例均为需审查的路线模板：

- 影像特征与组学数据进入预测模型：核对实体对应、数据划分和变换来源；没有明确映射时禁止按顺序拼接。
- 差异结果进入通路或网络分析：核对标识体系、分析背景和结果单位，转换与筛选显式记录。
- 网络候选进入结构计算：候选来源、分子/靶点身份和相应结构/工具前提单独核查，不能因网络连通就默认结构计算可行。

这些组合共享project.json、任务/产物依赖和证据链；不在不同领域的“子库”之间复制课题状态。一个方法跨多个领域仍引用相同规范id，项目使用的具体分支和输入范围分别记录。

## 6. 运行契约补齐

现有runtime_contract.py对包依赖映射只允许R/Python键。v1.1要求在保留旧格式语义的前提下设计兼容扩展：

- 入口类型：已有函数入口，以及脚本/外部程序/已有流程的声明；具体支持者逐项注册。入口存在不证明已运行。
- 软件条件：R/Python包仍按现格式；外部工具另记名称、版本约束/实际版本、平台和路径/指纹，不伪装成Python包。
- 计算条件：按实现需要记录CPU/GPU、驱动/加速运行时、内存/存储和许可证条件；未核查项保持未知。
- 资源条件：模型权重、参考数据库、字典、受体/配体及参数文件均以角色、版本、路径/哈希或可核查来源记录，避免全拷贝不相关资源。
- 调用与证据：用明确程序/参数/工作目录描述实际执行；agent在课题环境运行。纯元数据命令与网页不执行这些声明。

新字段的后端解析、代码/资源查看、lint、API与前端展示同源；版本不支持时明确提示。不仅解析R/Python包，还要能记录其他运行条件。只声明新工具或硬件不授予算法verified，也不授权安装、付费、创建环境或下载权重。

旧清单保持原指纹/语义，新增实质依赖变化才触发相应证据重核；不能因空字段升级使全部旧收据无故失效，也不能用迁移给旧收据补造从未核查的条件。

## 7. 领域分类与入库同步

现有领域tags与用途purposes继续来自后端/既有受控词表。T00/T01审查其能否表达新范围；必要时扩充和迁移，保留旧id与历史引用，不把新领域全部归为“其他数据图”。

领域配置不另造一份与tags竞争的领域词表：它引用已有领域/方法/接口，并按数据对象与实际任务组合。领域标签用于浏览；科学适用性由前提证据决定。新增领域或模态一般通过配置、语义契约和必要输入适配器接入。

入库八步从首轮补上：原生对象/实体与单位、领域配置依据、运行工具/资源、前提声明、结果检查和跨域适用范围。SKILL不把“课题还能做什么”路由到仅单细胞流程，前端显示范围与实际验证一致。

## 8. 跨领域验收，不以单样板代替通用性

- G0：上述所有领域有可检查的代表配置/任务，使用同一内核表达完整与不完整材料，验证前提、状态、缺口、依赖和草稿；不运行算法的部分明确标结构/规则测试。
- G1/G2：按D019使用青光眼真实课题分别检验工程实跑与状态/推荐适用性；癌症案例保留后续可选验证，不能把癌症专用前提套入本样板。
- G3：至少两个非单细胞领域的实际具体分支复用与结果/图检查，含原生非表格对象或文件；依据现有资源选例，确实无法运行则保留缺口，不假报通过。
- 开放性：一个不在初始清单的新领域可以登记对象/语义/前提并提出配置扩展，不要求改内核强制细胞字段；未注册的自动解析/运行能力清楚提示待适配。
- 组合性：跨模态任务的身份/设计/依赖对齐要有证据，不自动拼表、借用验证范围或改变研究单位。

具体场景见[handoff.md](handoff.md)的A17–A25；A25额外要求从真实agent调用skill进入完整流程。最终报告按“领域配置覆盖／具体实现可用／实际调用／科学判断审查／作者确认”分别列证据，避免一张全领域支持勾选表掩盖缺口。
