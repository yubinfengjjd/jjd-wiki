# GitHub 收尾与 DE 会话隔离修复

目标：按当前证据完成 Issue/PR 审查与 CI 收尾，修复 DE 入口对调用方会话的副作用，清理已完成分支。作者已明确不安装新增 R 依赖；未完成的后端与原样配方运行不冒充通过。

1. 核对两个仓库的当前 main、PR、Issue、受保护作者块和各执行收据。按实际目标关闭已完成的分类/资料问题；保留完整运行尚未完成的问题。
2. DE 的原生 `de_native.R` 不变。公开入口每次使用同一 R 安装的新进程，先设置原库路径再反序列化输入；成功返回结果，失败传回日志并清理临时文件。不再尝试删除已加载命名空间需要的初始化选项。
3. 使用现有公开 pancreas 数据验证：同一父会话两次调用、完整 options/search/libpaths/RNG/输入不变、原实现 DE tools 精确一致、子进程失败传播和临时目录清理；另在异目录（含空格）调用。保留原失败探针及旧收据，新收据只绑定新入口的实际范围。
4. 同步 FeatureStatPlot/FeatureCorPlot 的计算与检验触发边界、历史缺包探针与当前本机状态。保留原字节、旧收据和作者确认，不扩展未执行形态的验证。
5. 依次 save、依赖清单哈希重绑、check-entry、lint、protect-baseline、guard、CI、独立评审、仓库合并门禁。运行与科学有效性、浏览器验收分别报告。

安装限制：本次不安装 scDblFinder、SingleR、monocle、RcppML、harmony、batchelor、scmap 或其依赖。旧收据在记录环境通过不代表这些包在当前本机已存在。
