## 具体验收方式

### V01 方法家族与代码能力分离

输入一个只含具体模型原实现的来源。检查家族目的、原实现、条件、限制和未验证分支都有记录，未凭空补算法；查看代码仍能找到原字节文件。不能出现“任意模型已支持／已验证”无证据表述。

### V02 关系多对多

构造有明确语义的隔离夹具：M_A 可配 F_A/F_B，F_B 同时可配 M_B，另外加入列名相似但粒度不同的 M_C。M_A/M_B 为软件测试对象，不据此新增真实科学结论。

检查方法页、图页、反向查询与图谱同步显示前两类联系；M_C 不变为直接可接。新图来自另一来源时仍能发现 M_A/M_B。更新与归档后不会留下可执行误导。

### V03 两种课题入口与数据差异

用隔离课题夹具保存目标说明、运行记录、结果表。分别问“还能做什么分析”“已经跑完，选适当的可视化”。

- 列名不同但含义一致：候选找到、提出映射，选定后在副本转换，原表哈希和关键值不变。
- 长宽表转换：按键与数值验证可还原，不无脑比较总行数。
- 同名不同量纲或数据单位不清：列差异并询问，不当作 direct。
- 缺模型／特征等关键材料：分到补材料候选，不伪造这些对象；已有结果的选图仍可单独进行。
- 没有合适库存：说清未找到，不能编造方法或可运行模板。

### V04 代码浏览真实连接

准备至少一个含原版/复用版、多文件的 Python 例子和现有可用 R 文本材料；若没有真实 R 素材，用明确标识的界面夹具检查读取，不宣称验证 R 算法运行。

从方法卡和图卡点击查看，切换文件与版本，复制与下载；核对下载字节哈希。无代码、片段、未知编码、错误路径都有明确结果，不执行代码或输出中的脚本。确认三处安装与正式端口实际提供同一版本。

### V05 迁移和回归

对比基线：两篇旧笔记归档、有效内容并回相应家族、用户备注不变、原始画廊和成图哈希不变，无断链和自动签核。检查两栏图库、预览降级、归档删除、任意合法 n 的已有检查继续通过。扩展关系字段后，删除的影响范围预览与审计也应覆盖这些字段。

### V06 agent 交接

用新上下文分别检查 Codex 与 Claude Code 安装规则读取路径和推荐流程：能根据同一课题摘要找到方法，说明证据／缺口／代码状态；不会仅因接口字符串不同就跳过，也不会以表头一致证明科学适用。先检查是否存在可用环境与授权，不能伪称已做跨宿主真实运行。
