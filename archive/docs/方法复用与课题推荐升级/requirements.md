## 目标与使用场景

Wiki 保存有来源、可理解和可复用的方法与单 panel 图样。Codex、Claude Code 在作者当前课题中读懂研究目的、数据与进展，再从 Wiki 找可继续的分析，或为已有分析结果挑选可视化。Wiki 提供知识、关系和代码，不在网页内运行分析。

两个主要入口：

1. “课题还能做什么分析”：读当前课题的必要资料，给出与目标相关的后续方法、前提、数据缺口、代码状态与可配图样。
2. “分析已经跑完，选适当的可视化”：检查实际结果表的含义与粒度，推荐合适的单 panel 图样或模板，说明能直接调用还是需适配。

## 必须保留的边界

- “XGBoost＋SHAP → 适用的机器学习模型＋SHAP”是用户给出的推广方向；具体哪些分支适用、何种代码已支持、何种解释器选择有依据，需分别核实。不得写成无条件支持所有模型。
- 方法可讨论哪些对象，不等于某份原始代码已经支持这些对象。方法页确认、代码可用、实际验证是不同状态。
- 原始代码保持原语言与原字节，复用改造另存。只有片段时写“片段”；重建代码不能标作原作者完整实现。
- 列重命名、表形状整理不包含：隐式聚合、补样本、重新计算统计量、改变缺失值处理、单位换算、阈值或验证划分。后几类需按具体差异询问，不能借“适配接口”静默改变分析。
- 不修改原始课题数据、不覆盖 Wiki 原生代码；必要副本、适配脚本和产物放当前课题。
- 只收录单 panel。inset、边缘分布、色标可属于同一逻辑 panel。完整原图继续只读溯源，整图不重新进入前端。
- 原有签核、归档、删除、用户备注保护继续有效。新的关系录入不自动签核来源、不自动把模板变为 ready。
- 本轮不新增数据库、独立代码库、网页执行平台、后台模型服务或新的全局 Python/R 环境。

## 推荐交付给作者的内容

每个候选至少说明：要回答的问题、为何符合当前课题、依据了哪些项目资料、Wiki 方法／图样出处、当前所需输入与已有材料、缺口或适配动作、代码是否存在及验证范围、相关图样、下一步由谁做什么。

“当前可做”“需要补材料”分区；“待核实”明确不等于可执行推荐。不存在合适库存时如实说明，不能虚构 Wiki 方法或图模板。

选择具体方案后的执行仍沿用既有流程：作者选定 → 课题环境检查 → 已授权的适配／分析／出图 → 检查结果 → 记录使用。此次访谈不授权立即运行课题或归档旧页。

## 验收清单

| 场景 | 可观察结果 |
|---|---|
| A01：收录一个具体 XGBoost＋SHAP 示例 | 家族说明保留原实现，列前提和未验证分支；不生成“任意配对值比较”等广泛迁移方法 |
| A02：一个方法适用于两种图样 | 方法页、两张图页及图谱均可追溯同一关系，理由和兼容状态一致 |
| A03：新图样可对应两个已有方法 | 新图入库时反向检查两种方法，不因属于不同帖子遗漏；不制造重复图样或新接口来硬连 |
| A04：列名不同但语义已确认 | 候选仍被找到，明确映射差异；在课题副本适配后可供模板检查，源表不变 |
| A05：列名相同但含义或每行单位不同 | 不显示为直接可接；指出差异并询问或列为待核实，不直接画图 |
| A06：已有预测表但无训练模型／特征材料 | 不把依赖这些材料的方法标为当前可做；有研究价值时说明需补什么；也能独立寻找已有结果的可视化 |
| A07：多文件 Python/R 代码 | 方法卡与图卡均有代码入口，列表可切文件、区分原版／复用版；下载原文件哈希不变，网页不执行 |
| A08：只有原始片段或没有代码 | 明确显示片段／暂无代码；不伪造复用函数、验证状态或已运行结果 |
| A09：完成一次课题适配 | 映射与检查记录留课题；未经新的回存确认，不修改全局代码、接口或原生文件 |
| A10：迁移旧内容 | 两篇旧迁移笔记归档；有效内容并回对应家族；来源、作者备注、历史成图和可用单 panel 不丢失，无断链 |
| A11：重启与跨 agent 续用 | Codex、Claude Code、.agents 三处技能读取同一 E 盘库，新会话能解释推荐依据及适配边界 |
| A12：历史功能回归 | 两栏图库、归档删除、预览降级、任意 n 与来源保护行为继续通过相应检查 |

验收场景的接口夹具和数据规模由执行者按实际代码准备，不能把示例数量写成支持数量白名单。合成夹具只证明流程和软件行为，不代表真实课题科学有效。
