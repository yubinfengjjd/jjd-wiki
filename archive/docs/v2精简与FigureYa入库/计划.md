# v2 精简与 FigureYa 入库：实施计划

日期：2026-10-27。作者选择：1=a（SCP 暂停，v2 落地后重排）、2=a（大幅放开治理）、3=a（FigureYa L0 全量 + L1 30 个 + L2 示范 3 个）。

## 目标

1. 规则短而准：agent 日常“找模板并调用”只需读 SKILL.md（约 80 行）与命令输出；AGENTS.md 只写底线与页面分工（约 120 行），细节契约放 references。
2. 开源库与复刻代码可批量入库：来源登记 + 适配器，不经画廊。
3. 任意 agent 可用：`catalog.jsonl` + `rwiki find / show / use`，全局说明各加 3 行指路。
4. FigureYa 首批入库并可原样运行。

## 数据模型 v2（新增，旧页不动）

| 级别 | 存放 | 含义 |
|---|---|---|
| L0 | `sources/<来源>/items.jsonl` 一行一项 | 目录：用途、输入、依赖、许可证；可被 find 检索，未建页面 |
| L1 | `recipes/<id>.md` + `recipes/<id>/source/`（原字节）+ `runs/` | 整个上游模块，在 Wiki 专用环境原样运行，有运行收据 |
| L2 | `templates/`、`methods/` | 函数化、可换数据；沿用现有回放/收据 |

- 新页面类型：`source`（来源登记：URL、commit、许可证、适配器、是否白名单）、`recipe`（L1 配方）、`scenario`（场景导航：首选组合）。
- 模板可以只记 `sources`（如 `recipes/<id>`），不必有 `layouts`；`layouts` 页保留为历史来源记录，不再新增。
- 新条目状态统一 `draft / ready / archived`；旧 layout 的 `pending_*` 保留只读。能否执行看级别与收据，不看状态。
- 新运行收据一种格式（`runs/<时间>.json`，`scope` = as-is / new-data / other-dir）；旧回放、实现、独立性收据只读保留。
- `catalog.jsonl` 由 save 生成：L0+L1+L2 每项一行（id、级别、场景、图型、输入、依赖、许可证、状态、调用命令）。

## 治理 v2

- 知识库可在本地 `main` 直接 `save` 提交；`task/*` 分支仍可用（写入锁只在 task 分支生效）。
- Issue / PR / 他人评审改为可选；pre-push 不再拒绝 main，内容扫描（画廊、GPL/NC 源码、课题数据、超限、绝对路径）保留。
- 限制性许可（GPL、CC-BY-NC、CC-BY-SA）的源码目录自动进 `.gitignore` 托管块，不进 Git、不推送。
- deploy 门禁：开发仓库干净且 HEAD 为本地 main 或 origin/main 即可部署；部署目标加 `.kiro`；references 中的过期文件随部署清理（先备份）。
- Wiki 专用 R 库 `E:\research-wiki-env\R-lib\figureya` 按批次列清单、作者批准一次后安装；不碰课题环境。
