# 方法与绘图最小依赖独立模块设计

日期：2026-10-23。状态：作者已确认设计方向并授权先成文后交 Claude Code 实施，Codex 审查；不重复询问实施许可。

## 作者要求及现状

作者确认：SCP 主要整合多个底层方法；课题使用 Monocle2 时只需 monocle 及其必要依赖，使用某种图时只加载该图必要的绘图库/辅助函数。完整来源库留作原始溯源，不成为每个模块的运行条件。同步前后端、skill、入库规则，防止后续再次出现整库包装冒充独立方法。

当前多数分析入口仍要求 bundle 并校验完整 SCP-local 的绘图/资源/Python 文件，之后加载整套 R 文件。与此不同，16 个 SCP 图模板已含局部原生绘图核心和局部 helper，必须逐个检查，不能因为文件名含 SCP 就认定依赖整库。当前方法分类、灵活 bindings、单 panel、来源/回放、逐分支验证及作者确认成果均须保留。

## 方案选择

1. 采用：按分析任务/实现分支提取最小调用闭包，成熟算法直接用其正式包；SCP 特有处理和绘图保留原生核心及必要辅助代码。
2. 不采用作为默认：只改为按需加载完整 SCP-local。它仍要求复制整套库，不满足独立迁移。
3. 不采用：用自写算法或近似 ggplot 重画代替原生实现以减少依赖。依赖减少不能改变分析含义、默认流程或图形编码。

这是运行架构改造，不再新造方法分类。一个规范家族可有多个算法实现，每个分支有自己的入口、复制文件、必要包、可选功能及验证范围。多个模块串联仍记 workflow；技术源码归档仍为 technical。

## 范围

- 审计全部已入库方法/模板代码，明确 SCP 整库依赖、已独立实现、非 SCP 无需改动三类。
- 重点迁移当前 SCP 分析分支，覆盖质控、双细胞、降维、整合、注释、差异、富集、评分、轨迹、动态特征、参考映射、RNA velocity；已直接用 Seurat 的聚类/参考映射核对而不盲改。
- Monocle2/Monocle3：从现有固定版本 SCP 原代码提取到已有 trajectory-inference 家族的具体分支，保留原逻辑；若本机缺包，只登记静态提取和精确 not_run，不以此声称已运行。
- 16 个现有 SCP 单 panel 模板逐一核对依赖、局部 helper/资源、异目录直接调用和 render；已独立且声明准确的代码不为凑改动重写。
- 其他上游未入库函数保持原始归档，不批量新增页面或宣称整个上游包均已拆解。

## 模块契约

每个具体实现应能回答：做什么、实际支持什么输入、输出什么、复制哪些文件、需要哪些包/资源、可选功能需要什么、依据和验证是什么。

- 核心分析与对象转换分开。原生对象/矩阵入口仅在确实实现时声明；保留现有 Seurat 调用兼容，不强制所有方法转 CSV。
- mature 包自身的传递依赖仍然必要。最小依赖指所选实现需要的闭包，不等于只有一个包，也不要求拆掉上游合法 Imports。
- 分支间延迟检查依赖。source 一个含多个入口的局部文件不应立即要求所有分支的可选包；只在调用对应功能时检查，缺包明确失败且不安装。
- source 不能运行分析、下载数据、初始化无关 Python 环境、修改永久 options/.libPaths/search path 或自动安装；受控临时改变须恢复，随机性和并行配置明确。
- 不通过全局对象、工作目录、Wiki 路径、完整 SCP 文件树或隐式网络寻找代码/资源。局部资源随复制清单携带；允许正常调用底层包的资源。
- 数据/结果/参数均显式传入。输入不变；不静默过滤、补值、聚合、换算、换模型、重新训练或换统计默认。项目需这些动作时由课题明确决定。
- SCP 自己的辅助函数/绘图核心原语言保留，修改副本与原始字节分开。对上游捕获错误后返回空/旧对象的行为，外围须检测真实输出；必要的失败即报错改动要写明，不伪装数值等价。
- 接口兼容层可接受旧 bundle 参数但不能再使用或读取整库；弃用说明清楚。若无法保持某入口兼容，须保留旧实现并新增独立分支，不悄悄覆盖。

## 运行清单与后端事实

用一个共享小模块读取方法分支/模板的运行清单，不增加数据库、执行平台或包发布系统。建议清单作为资产 JSON（相对路径引用），至少包含版本、入口、运行模式、需要复制的代码/资源文件、必要包、按功能分组的可选包、来源/修改说明。字段具体形式由 Claude 按现有结构做最小实现，首次定稿写进 implementation-plan 的执行记录与 references，方法与模板不另造两套事实。

- 运行模式：standalone（独立模块声明）、bundle（明确整库依赖）、unknown（历史未审计）。
- 声明独立与验证独立是不同事实。另派生 portability 状态及证据；仅有 JSON 或静态检查不能显示“独立运行已验证”。
- 保持 implementation_status 的实际算法 verified/not_run/stale/invalid 含义；独立性与算法验证两个轴，不用独立性证据批准算法。
- 清单路径限制在条目资产内，拒绝越界、符号链接逃逸、隐藏路径、缺失文件、重复/无效声明。API 只读，不扫描课题任意目录、不检查服务器安装包冒充课题环境。
- 运行清单、入口、helper、资源及其依赖声明变化必须使相应独立性证据过期；算法相关变动使旧算法收据过期。保留旧证据，不修改历史收据冒充重新执行。
- 当前算法收据可继续保守绑定 code/ 全文件；不为减少失效而降低原有证据门槛。

## 前端

方法具体实现、模板详情及代码查看器从同一后端事实显示：运行方式、必要依赖、可选功能依赖、需要复制的文件、独立迁移验证范围。默认简短，详细清单折叠/可读可下载，不能把长技术清单再堆回用途介绍。

明确区分“独立模块，尚未运行”“独立迁移已验证”“仍需完整来源库”“历史依赖待审计”。不把作者 ready、文件存在、source 成功、来源图或旧封装收据当成新模块验证。保持领域→用途、搜索/计数/URL、图库两栏、来源/回放标识、旧 id 和作者入口。

## 入库及 skill

正式 知识库/AGENTS.md、staged/assets/AGENTS.md、SKILL、method-families/project-reuse/code-assets/source-functions/llm-wiki-mode 等实际存在的相关 references 同步：
