# research-wiki · 需求

依据：`session.md` 决定 D001–D055（2026-10-20）。前端风格经两次返工，以 D038–D043 为准（取代 D017、D028–D037）。

## 目标与场景

一个本地 LLM Wiki（D018）：知识以 agent 维护的互链 Markdown 页面为本体，配一个薄的本地服务与浅色“期刊插图”风格前端。

- 首版（D003）：把 sci-figure-replica 复刻好并签核的图抽成可换数据的模板；用户在新课题中让 Codex / Claude Code 出图时，agent 从 wiki 推荐 2–3 个候选，用户确认后套用。
- 第二版（D005）：文献/方法/创新思路页面，来源为 Zotero、已有笔记、用户提供的 PDF；并入同一 wiki 与 3D 网络。

使用者：单人（作者本人）+ Codex / Claude Code 两类 agent（D008）。

## 范围

首版做：
- wiki 骨架：模板页、场景枢纽页、图型枢纽页、课题页、`index.md`、`log.md`、规则文件（D019）
- 复刻 → 自动收录 → 网页签核 → 待办 → agent 抽模板并回放验证 → 推荐 → 确认 → 套用 → 回写使用记录（D007、D012、D014、D022）
- 本地服务 + 前端：画廊、模板详情、枢纽页、课题页、3D 网络、待办/归档、日志（D011、D015、D025）
- 改造已装技能：sci-figure-replica 末步收录；medfig-render、medpaper-pipeline 出图前查模板（D022、D023）

首版不做：文献页面与导入；期刊风格预设（D010）；向量检索（D016）；本地服务调用任何模型（D012）；网页真删除（D015）；多人协作。

## 分析方法库（第 1.5 版，D045–D059）

可复用的分析代码（生信为主）作为“方法”收入同一个 wiki，改参数即可在新课题复用；方法与图模板之间通过“数据接口”连成“分析 → 出图”链。

| ID | 需求 | 依据 |
|---|---|---|
| R16 | 方法是一张 wiki 页（用途、原理、适用/不适用、参数含义、输入输出接口、来源/许可证/应引用论文、作者备注），代码、参数清单、示例数据、示例输出是页面资产 | D058, D052 |
| R17 | 收录来源三种：公众号帖子的分析代码（随复刻收录，与同帖图直连）、作者课题脚本、GitHub/论文代码（需联网，先征得同意） | D045 |
| R18 | 一步一个方法；方法声明输入接口与输出接口，前一步输出接口等于后一步输入接口时可串联 | D054, D056 |
| R19 | 数据接口：标准表格式（列名、类型、含义）各为一页，按数据本身定义、与模型/工具无关；方法最后一步输出接口格式；图模板每张输入表声明对应接口；方法与图模板只经接口节点相连（多对多），同帖方法只在方法页记出处 | D056, D059 |
| R20 | 参数集中在参数清单（含义、默认值、合理范围）；套用时只改参数清单，不改方法代码 | D047 |
| R21 | 方法“可用”门槛：示例数据（每个方法约 20 MB 以内，存进知识库）在本机跑通、保存输出、输出符合所声明的接口，作者确认后才可推荐；真实数据留课题目录 | D046, D049 |
| R22 | 运行环境：共用一个生信专用 Python 环境和一个专用 R 库目录；方法写明依赖与版本；缺包列清单征得同意后才联网安装；不动作者已有环境 | D048 |
| R23 | 推荐与套用：agent 成套推荐 2–3 套“方法 + 可接的图”，写明要改的参数；同一张图有多种方法时按适用条件对比并给首选；作者选定后连续执行分析→检查输出→出图，仅在报错或结果异常时停下 | D053, D057 |
| R24 | 方法与接口作为新节点类型进入知识网络；“方法→接口→图模板”连线带箭头；只有收录进知识库的方法才出现 | D051 |
| R25 | 无许可证的外部代码标“仅供个人研究参考”，套用时提醒 | D052 |

## 质量要求（硬要求）

- 不写屎山代码与防御性代码（D002、D018）：不为不可能的状态写兜底分支；错误在边界处一次性报告；不加未被需求使用的配置项、抽象层或兼容层。Claude 逐项审查 Codex 产出。
- 本地服务只监听 127.0.0.1，无登录（单人本机使用）；静态文件只从总库与画廊两个根目录提供，不能越出。
