## 发现

### F01 · P1：再次入库会绕过新版本的作者签核

位置：[ingest.py:114](E:/research-wiki/开发/staged/research-wiki/rwiki/ingest.py:114)。

当画廊仍携带先前的 `approved`，但 version 从 1 升为 2 时，第一次 ingest 正确设为 `pending_signoff`，同时把 `gallery_version` 更新为 2。第二次对同一条目 ingest，因为版本已相等，又命中 `elif pending_signoff`，自动改成 `pending_template`。整个过程未调用作者签核。

复现采用正式相同的 `single_panel_only=True`、单一 A panel，结果为 `pending_signoff → pending_template`。新版本审核被刷新操作替代，与“重复 ingest 不推进签核”的规则冲突。

建议：保存并核对“已明确签核的版本”，将其与“已读取的来源版本”分开；同一版本的 ingest 必须幂等。网页签核推进已签版本，重复 ingest 无权代替。对应 lint 的版本/状态判定也应一起调整，不能靠把状态改回去消除诊断。

### F02 · P1：模板可以没有回放就标为 ready

位置：[templates.py:219](E:/research-wiki/开发/staged/research-wiki/rwiki/templates.py:219)。

`mark_ready` 只加载 spec 并检查 `preview.png` 存在，没有要求成功的 `verify-template` 记录或相应 PNG/PDF/SVG。隔离模板未运行任何回放，仅放入一张普通 PNG 后，公开 `mark_ready` 正常成功，状态成为 ready，`verify/verify.json` 仍不存在。

用户确认授权与软件回放是不同验收项：用户允许标 ready 也不能证明代码跑过。此漏洞使仅有图片的草稿进入可用与推荐阶段。

建议：确认入口与 workflow 共用“当前版本完整回放”检查；未满足时保持草稿、明确缺项。历史模板的兼容方式单独声明，不能用迁移规则伪造回放。

### F03 · P2：修改代码后旧回放仍被当作当前回放

位置：[workflow.py:13](E:/research-wiki/开发/staged/research-wiki/rwiki/workflow.py:13)、[verification.py:9](E:/research-wiki/开发/staged/research-wiki/rwiki/verification.py:9)。

回放 receipt 只有时间和 exit_code；`replay_available` 仅比较已有输出文件与预览图。成功回放后，把当前 render.py 替换为立即抛错的脚本，仍得到 `replay_available=True`，队列仍显示 `template_confirm / confirm`。

这会把实际应继续回放的工作交给作者确认；当前 mark-ready 的 F02 也不会阻止该错误。此次没有宣称正式库模板已被改坏，这里验证的是状态判定的可复现漏洞。

建议：receipt 记录执行前代码、spec、接口、示例数据及覆盖样式的哈希，记录输出哈希和运行环境。输入变化、失败重跑或输出不一致时旧 receipt 失效；workflow、确认入口和 lint 读取同一判定。

### F04 · P2：空白方法骨架可确认并被推荐

位置：[methods.py:63](E:/research-wiki/开发/staged/research-wiki/rwiki/methods.py:63)、[workflow.py:47](E:/research-wiki/开发/staged/research-wiki/rwiki/workflow.py:47)。

刚 scaffold 的方法，所有正文节均空，已经被派生为“待你确认”。调用网页相同的 `/api/methods/<id>/confirm` 返回 200；随后 lint 无诊断，suggest-methods 返回此方法，purpose 为空。确认函数直接从 draft 改成 ready，没有核查笔记是否完成。

建议：补方法笔记最小验收检查：用途、适用边界、输入/输出说明、来源、代码状态和知识关联检查是否有实质内容。文字方法可以没有算法、没有代码、没有直连接口，不得借修复此问题强制补算法。未完成骨架由 agent 继续处理；完成且符合检查后才交给作者确认。

### F05 · P2：同一模板复用到两个来源后，图库重复计算同一图样

位置：[figureModels.ts:36](E:/research-wiki/开发/frontend/src/figureModels.ts:36)。

`galleryEntries.single` 保留所有来源，只过滤被来源覆盖的模板，未合并来源之间的已证明复用关系。隔离夹具中两个来源均完整、双向关联同一个 ready 模板，图型与 A panel 结构相同；图库显示两个图样，而同一数据的 methodDisplayFigures 正确只显示一个。

这不是“要求两栏数量永远相同”：此例有明确同模板、同结构的复用依据，仍被重复展示。不同结构、未知覆盖不应被合并。

建议：图库与方法页共用基于明示覆盖的图样代表规则，在同一代表下保留多个来源链接。保持现有“两个浏览视图可以重叠”和 SHAP 三图可见行为，不重新入库、不生成待办。

### F06 · P2：名为当前索引的文档仍记载已失效状态与旧联想

位置：[当前要求与同步核查.md:17](E:/research-wiki/文档/当前要求与同步核查.md:17)、[同文件:34](E:/research-wiki/文档/当前要求与同步核查.md:34)。

历史维护报告允许保留当时快照，不应抹掉审计历史；这里的问题是当前索引仍被当作最新状态。新会话按此索引可能再次处理已完成工作。
