# 决策记录

本页记录被 v2（2026-10-27，计划见 [v2 精简与 FigureYa 入库](v2精简与FigureYa入库/计划.md)）取代的旧规则，以及仍然有效的作者要求。执行细则以 `知识库/AGENTS.md`（v2）为准；本页只说明改了什么、为什么改。

v2 的起因是作者的四句话：规则太繁冗，不利于管理；画廊不是必须的；以后会大量引用开源库或用 skill 复刻代码，在特定场景输出特定模板；Claude Code、Codex 等通用 agent 都要能用。

## 仍然有效的作者要求

原始材料与作者内容：

- 原始层只读：来源快照、画廊、配方与方法的 `source/` 保留原字节、哈希与许可证（D013、R2，v2 扩展到上游快照）。
- `<!-- user -->` 区块 agent 不改；facts 只由脚本生成；status、favorite、archived_from 只经 `wiki.py` 或网页改（D020、R11）。
- 不编造数据、文献、收据或适用结论；没跑写“未跑”，不确定写“待作者确认”（requirements 写作要求）。
- 限制性许可源码、课题数据、密钥不进 Git、不推送；FigureYa 为 CC BY-NC-SA 4.0，仅非商业、署名引用、相同方式共享（v2 计划）。
- 外部代码记来源链接、许可证与应引用文献；无许可证的标“仅供个人研究参考”（D052）。

分析与数据：

- 改变统计逻辑、补缺失算法、改分组含义，或缺原始数据需要估读/合成时，先问作者（当前要求表；D073）。
- 列映射显式写（内部字段 → 作者列），不猜列、不补值、不换算、不聚合；列名或长宽表不同不能作为排除理由，同名也不证明兼容（方法复用 R08、R09）。
- 有边界的方法家族推广（如 XGBoost＋SHAP → 满足前提的机器学习模型＋SHAP），保留原实现，列适用范围与未验证分支，先写文字（D068、D072，方法复用 R01）。
- 每次新知识双向检查一方法多图、一图多方法；直接可接 / 需要适配 / 待核实与实际运行验证分开（D069、D076，方法复用 R02、R03）。
- 推荐前读课题必要资料；优先列当前可做项，再列少量补材料后可做的候选；推荐后等作者选（D075、D078，方法复用 R06、R07）。
- 课题适配先留课题；有通用价值时提出回存建议，作者确认后才进 Wiki（D080，方法复用 R10）。
- 课题数据、脚本、成图留在课题目录；Wiki 只记路径与判断（D014、D049）。

模板与代码：

- L2 模板一个逻辑 panel，inset、边缘分布、色标随主 panel；先识别样式并去重，不全量复刻；开源库同样按主题分批、选择性入库（当前要求表；作者 2026-10-27）。
- 函数化保留原语言与源版本，原始版与复用版分开保存，可复制到课题直接调用；分析输出结果表，绘图读表，可分别调用或串联（当前要求表；D074）。
- 卡片“查看代码”只读：按文件浏览、区分原始版与复用版、可复制下载，网页不执行代码（D077）。
- n 为实际数据中的任意合法数量，按数据调整尺寸、标签、配色与间距；默认保持单 panel 与间距继续加宽，只有作者设上限才协商（当前要求表）。
- 图库保留“单 panel 图样 / 可调用模板”两栏（2026-10-21）。

工程与环境：

- 产品本质是 LLM Wiki，脚本与网页是薄外壳；不写屎山代码与防御性代码（D002、D018）。
- 本地服务只监听本机，不调用任何模型；不引入数据库、向量库或网页执行器（D012、D016、requirements 质量要求）。
- 正式路径在 E 盘 `E:\research-wiki`；临时文件与缓存不写 C 盘（当前要求表）。
- 多个 agent 的技能副本读同一个 E 盘知识库（R14；v2 为 6 处部署）。
- 不在主检出检出 `legacy/master`（2026-10-27 GitHub 结构化工作流，仍有效）。
