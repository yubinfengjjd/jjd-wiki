## 来源登记的当前限制

当前部署的 rwiki 适配器只识别 FigureYa Rmd。SCP 是 R 包，不能将函数导出伪装成 FigureYa 模块，也不能将普通 R 文件当作 Rmd 配方。本批用 `methods/scp-source-catalog` 提供可检索的技术来源索引，不宣称已经有 SCP 的自动 L0 `source scan/promote/run` 路径。

全量索引记录 142 个导出和 238 个顶层定义；未对每个内部 helper 另建分析页。10 月旧覆盖表的 79 个候选模块及 286 个具名分支继续保留为候选线索，不继承过期的通过状态。

Windows 历史检出存在 CRLF/LF 与 Git blob 的差别，实际文件与 blob 哈希分列。原始层保持只读，不能把换行归一化后的内容一致写成原字节一致。

## 检索与使用

```text
rwiki find SCP
rwiki show scp-source-catalog
rwiki find DynamicHeatmap --kind method
rwiki show scp-viz-heatmaps
rwiki use scp-viz-heatmaps --project <课题目录>
```

`use` 复制技术页的 code/ 和 runtime.json；在课题副本中选对应分支入口。Seurat/结果对象输入不交给 CSV 专用的 `render`，也不交给 Rmd 配方的 `run`。整库加载器仅用于历史兼容、审计和原版对照。

GPL 源码与派生代码留在本机 ignored 目录。页面、清单和收据可进 Git，不能仅凭 Git 检出就承诺异机已携带可执行闭包。
