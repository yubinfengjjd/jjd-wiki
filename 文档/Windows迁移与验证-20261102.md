## 准备界面环境

这些是目标电脑上的操作说明，本次未在本机或目标电脑执行依赖安装。请先让接手 agent 检查 Python、R、Node/npm 的现有版本与依赖清单；安装科学计算依赖前仍按 AGENTS.md 向作者列出一批清单。已有收据主要来自 Python 3.12 与 R 4.5.0 环境，换版本需要重新实测，不能继承通过。

以下 `$py` 指向目标电脑真实 Python，不能使用 Windows 商店占位程序；有 Anaconda 时可用其实际路径。R 路径同样按实机修改。

```powershell
$py = 'D:\anaconda\python.exe'
$rs = 'D:\R-4.5.0\bin\Rscript.exe'
& $py -X utf8 -m venv E:\research-wiki-env\wiki-python
$wp = 'E:\research-wiki-env\wiki-python\Scripts\python.exe'
& $wp -X utf8 -m pip install -r E:\research-wiki\开发\staged\research-wiki\requirements.lock.txt
& $py -X utf8 E:\research-wiki\tools\configure-machine.py --python-exe $wp --rscript-exe $rs
Set-Location E:\research-wiki\开发\frontend
npm ci
npm run build
Set-Location E:\research-wiki
& $wp -X utf8 开发\staged\research-wiki\wiki.py serve --no-browser
```

打开 `http://127.0.0.1:8765`。服务只监听本机。构建产物可由前端源码重建，不携带旧电脑 node_modules 或 Python/R 安装目录。配置工具只生成被忽略的 `config.json` 与工作目录，不装包、不运行分析、不覆盖已有配置；词表快照已随技能源保存，不依赖旧电脑的用户目录。此时 `python_exe` 是界面环境；科学分析需要的包和解释器经核对后单独配置。

若要把技能部署到各 agent：先检查新生成的本机配置，再用 `$wp -X utf8 tools\deploy.py E:\research-wiki-env\deploy-new-pc "新电脑部署" --sync-config`；它按哈希核验六份副本。两个仓库干净后可按技能说明安装 pre-push hook。不要照抄旧电脑 `tools/bin/rwiki.cmd` 中的用户解释器路径，部署前可一直调用上述 staged/wiki.py。
