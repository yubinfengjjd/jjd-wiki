# 跨领域课题复用闭环升级：设计与盲区调查 v1.1

日期：2026-10-24。需求依据：[requirements.md](requirements.md)及D017产品范围纠偏。以下结构与字段是顾问提出的实施设计，尚未写入产品；它们不冒充已经实现的能力或新的作者签核。

## 1. 战略判断

产品体验以D018为准：科研课题里调用research-wiki后，agent能判断当前适合的分析，并查库复制代码运行、输出精美可视化。下述状态、契约和依赖设计用于支撑这条体验，不应把维护记录、手动CLI选择或填写复杂表单变成作者的日常前置工作。

当前最值得投入的是把已有可复用资产连成一条可核查的课题工作链。单独增加方法数量，不能解决接手时不知道做到哪一步、结果版本混用、换会话丢失决定或同样的适配问题重复发生。

这条工作链面向生物信息学、深度学习、影像组学、计算机药物设计、网络药理毒理学、蛋白组学、代谢组学及跨领域组合。首轮即建立领域无关内核与领域适配契约；单细胞仅是首个完整实际运行样板。不能把在一个样板上验证，解释为产品只服务该领域。

首轮保留现有分工：Wiki 编译与提供判断和实现；课题 agent 理解问题、操作课题环境；作者决定研究主线和关键取舍。新增程序负责记录、核对与计算依赖影响，不声称用规则自动裁决科学价值。

## 3. 保留现有架构，补最小的课题状态层

采用课题会话驱动、课题本地记录、Wiki共享知识的方案。用户已选择会话主入口和单细胞首个实跑样板，同时明确产品跨领域。首轮必须验证通用结构与跨域适配；各领域具体方法的实现/验证深度按实际证据逐项记录。网页课题调度台仍是后续需求。

内核处理通用实体、对象、任务、产物、证据与依赖；领域配置声明上下文、阶段证据和前提；具体实现适配器处理原生输入与运行。详见[cross-domain-contract.md](cross-domain-contract.md)。配置可组合，例如影像组学与深度学习、代谢组与网络分析共享同一课题状态，不拆成独立子库。

数据与记录分层：

| 层 | 保存内容 | 不承担的职责 |
|---|---|---|
| 原始来源 | 画廊、source/original_code、来源commit/许可证/哈希 | 不接收本轮课题的结果副本或覆盖原文件。 |
| 编译知识 | 方法判断、接口含义、配图关系、经审阅经验、索引与追加日志 | 不充当临时任务队列或原始数据存储。 |
| 规则 | AGENTS、SKILL、references及代码校验契约 | 不用自由文字覆盖当前运行证据。 |
| 课题记录 | 当前问题、证据、候选/决定、运行快照、结果与依赖、待回写草稿 | 不冒充全库科学结论或作者签核。 |

前三层沿用现有LLM Wiki落地。课题记录是执行现场，与现有wiki-use整合，不新增第二个分析执行器或工作流语言。Karpathy原文直取在本轮超时，本轮一致性核对以现有llm-wiki-mode及AGENTS为依据；原始[模式出处](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)仍保留，不宣称外部认证。

## 4. 课题本地结构与唯一事实

保留已有wiki-use/<本次标识>/context.json、mapping及结果记录。新课题默认增加一个稳定记录目录wiki-use/_project/；已有目录冲突时先检查版本并提出迁移，不覆盖。

    <课题>/wiki-use/_project/
      project.json             当前唯一状态、修订号、内嵌事件/决定历史
      summary.md               从状态生成的简短接手摘要
      routes/                  主线卡及其证据/作者选择的说明
      runs/<run_id>/           不可覆盖的命令、日志、输入输出清单、收据
      lessons/<draft_id>.md    经验草稿、证据、适用条件和审阅结果

分析代码、数据和图继续放课题已有目录；状态只引用它们。路径优先为课题相对路径；外部只读数据根由作者明确登记。移动课题后按登记信息检查，不把旧绝对路径失效误当文件已删除。

project.json拟包含以下概念。具体命名可由实施者在兼容测试下细化，含义不得省略：

- schema_version、project_id、revision、明确的project_root及登记的数据根。
- entities/objects/profile_refs：实体类型/身份及关系，原生数据/模型/文件类型、格式与版本，所用领域配置和适配器的版本引用；不强制cell_id、Seurat或CSV。
- observations：关于输入、历史步骤和结果的具体声明、证据位置/指纹、检查时间、来源是已核查/作者自述/未知，以及证据实际支持的范围。细胞注释、影像分割、模型训练或分子准备等阶段由相应配置表达，不放入全库固定阶段枚举。
- questions/routes：研究问题、主线版本、假设、替代解释、预期信息增量、作者选择与依据。
- candidates/tasks：规范家族id、实现id、所用代码/工具/模型资源快照、目的、材料与前提、授权引用、原生输入输出和诊断。
- artifacts：实际文件/对象摘要、输入/代码/参数/资源/环境指纹、产出run_id、依赖、当前有效性及原因。
- decisions/authorizations：作者明确决定的内容、来源、范围、预算及被取代关系；不从沉默生成决定。
- lessons：草稿路径、拟更新规范页、证据、审阅状态；正文留草稿文件。
- events：有稳定id和修订号的状态变更、运行登记与决定摘要；不保存模型思考或完整对话。

首轮避免额外数据库：锁定单写者，在expected_revision匹配后校验并原子替换project.json。运行产物先写入独立run目录、检查完成后登记；摘要可重建。写入中断不得把半截结果登记为完成；并发更新不得覆盖其他会话决定。旧版context保留，迁移通过引用和显式映射完成。

课题状态写入只影响指定课题，不调用正式Wiki的save。只有正式使用记录或经审阅入库才进入原有Wiki保存链；同步修订“所有写操作都save”的表述，避免每次更新课题进度就提交正式知识库。

## 5. 把不同判断分开

| 判断轴 | 例子/规则 |
|---|---|
| 声明依据 | 已核查的某范围、作者自述、未知。对象中有注释列，仅证明该列存在，不自动证明注释生物学正确。 |
| 工作状态 | planned/running/completed/failed/blocked/skipped；不得仅凭退出0写completed。 |
| 结果新鲜度 | current/stale/unknown；必须说明相对哪个数据、参数和代码版本。 |
| 知识与实现状态 | 沿用正式Wiki的作者状态、算法收据、runtime独立性，互不授予。 |
| 研究角色 | 主线、探索；缺材料是前提轴，主线分析也可能暂缺材料。 |
| 解释范围 | 待审、限定支持、存在分歧；针对具体主张，不能为整个课题盖科学有效章。 |

候选展示仍按用户希望的主线/探索补充/需补材料组织，但内部不将这些当互斥科学属性。“尚未入库”和“缺材料”可以同时出现。

首轮的已完成判据是声明范围内的证据充分：实际命令与执行记录、输出断言、输入保护及必要诊断。单纯旧文件可以列为已有产物，运行过程未知仍如实标明。完成是软件/步骤状态，解释与研究结论另审。

## 6. 从课题状态到候选路线

1. 读取既有计划、研究设计、实体/对象摘要、必要结果与日志，构造按分支的证据清单。身份、单位、来源和关键设计字段不明时集中询问；具体前提由实际任务和领域配置声明。
2. 已有明确主问题则复用。缺少主问题时提出2–3条主线，分别写当前证据、待检验假设、材料、方法与验证缺口，以及会改变后续路线的观察。
3. 组合两类信息：规范Wiki资产的可用能力；经过来源核实、可能相关但未入库/未验证的机会。库存检索分数只是线索。
4. 每项候选检查研究目的、对象/统计单位、数据版本、前提、相邻结果要求及实际实现。条件用满足/不满足/未知，并附证据；未知不能默认为满足。
5. 展示明确的覆盖范围、候选和未覆盖项。没有数据依据时不能把所有癌症项目都接到固定的恶性识别—轨迹—通讯链上。
6. 作者选择主线和执行范围，生成依赖与运行约定。候选改变需说明原因，并保留已舍弃路线及反证。

调用skill即进入上述流程：agent先复用已有课题上下文、主线、预算和决定；可独立完成的核查/常规步骤连续做。只有尚缺的重要决定集中询问，不为每次检索、复制、映射或绘图重复确认。当前目标与授权足够时应交付实际分析/图，不停留在推荐清单；缺实现或未验证分支则如实说明缺口，不能假报已跑。

拟增的机会发现入口可命名discover-methods：只读列出规范analysis笔记及其未验证分支，明确不可直接执行；库外机会必须附原始方法来源，未找到家族时仍留课题候选。现有suggest-methods默认过滤、返回语义及ready_for_use不得为“列全”而放宽。名称和参数在T02固定并测试，不能把设计中的命令写成现有命令。

进入当前可执行清单需要逐项通过：作者选定范围、研究/材料前提核查、具体分支当前验证、runtime闭包可复用、课题环境与输入契约核查、预算与权限。需诊断运行的待验证分支另标实验性，不伪装正式可用；是否补齐按D009请作者决定。

## 7. 跨步骤和跨会话需要知道的事

依赖图是实际课题产物与脚本的关系记录，不是另造一套算法流程。边包括：使用某输入、由某运行产生、受某参数/资源影响、为某主张提供证据。结构可连接不等于科学上能互证。

首轮应覆盖以下变化：

| 变化 | 处理 |
|---|---|
| 注释、纳入样本或输入数据版本改变 | 比较已登记的实际依赖，标直接/间接受影响项；预算内按顺序更新，保留旧run。 |
| 数据划分、模型权重、ROI、结构准备或组学标识/资源改变 | 按实际领域配置与运行依赖判断受影响项；不将所有变化都当作需要重新训练，也不套用单细胞注释逻辑。 |
| 图的配色/字号改变 | 只更新依赖这些样式参数的图；不因此重跑上游算法。 |
| 本地执行代码、关键参数或基因集/参考资源改变 | 标依赖结果需更新/核查，显示原因与版本。 |
| Wiki有新版实现，但课题仍用原快照 | 提示可用更新；不能静默替换课题代码，也不能仅因新版存在认定旧结果错误。已知纠错需单独评估影响。 |
| 环境版本变化 | 新运行前复查兼容性；旧收据保存其原环境，不能重新绑定为新环境已验证。 |
| 依赖未登记或无法精确拆分对象变化 | 标unknown并保守列出可能影响范围，先核对；不伪称精确跳过所有无关计算。 |

先用文件级指纹作保守检测。仅在已导出并核对counts、标签、嵌入等独立视图的实际指纹时做细粒度跳过；不能凭文件名、mtime或agent猜测证明未变。原始矩阵哈希开销需测量，不承诺每轮全盘重算。

这一设计借鉴了[W3C PROV](https://www.w3.org/TR/prov-overview/)对对象、处理过程、责任来源和派生关系的区分；重算触发因素参考[Snakemake官方CLI说明](https://snakemake.readthedocs.io/en/stable/executing/cli.html#execution)中输入、代码、参数及软件环境的区分。这里只借鉴记录原则，首轮不引入这些框架或宣称符合其全部规范。

检查发生在会话接手/恢复、运行前、登记新运行后及引用结果前。换会话先读summary和状态，再检查关键指纹与未决项。过期图仍可查看历史版本，但不能未经提示作为当前结果导出。

运行去重基于任务、输入/代码/参数/资源/环境指纹和完成检查。running记录在会话中断后只代表过程曾启动；复核准确进程与产物，不能按文件或PID存在就认定完成，也不盲目重启同一计算。

## 8. 执行、异常和图

agent使用课题指定运行环境及显式命令执行，Wiki服务不接收任意shell、不代跑分析。runtime.json仍是实现运行条件的单一事实；兼容扩展外部程序/脚本、模型/数据库资源及按需硬件条件，R/Python包保留原语义。具体入口/格式/工具未支持或未核查时明确标识；缺依赖保持精确not_run，按照用户现有约束不安装、不切换环境，不以外层R/Python包装掩盖外部条件。

运行约定记录：允许的任务/诊断、每阶段预算、并发、输出根、下载/付费权限、停止和重试条件。启动前比较预估与预算；实际使用量写回。未具备硬限制的资源只标估计/监测，不能宣称操作系统级强制限额。自动重试限于明确允许的暂态运行故障；更改统计参数或反复试出“理想结果”不属于自动重试。

结果不支持主线、方法冲突及诊断失败均保留：先查输入身份/版本、代码与参数、执行环境和约定稳定性，再给作者当前可支持的判断、缺口及路线。独立无关分支可以在原授权内推进，受影响分支等待决定。

结果解释需核查数据设计。例如，[Squair等的原始研究](https://pubmed.ncbi.nlm.nih.gov/34584091/)展示了单细胞差异分析中忽略生物学重复变异导致假发现的风险。本设计据此要求明确供体/样本/细胞层级；不会把某个marker检测分支运行通过，推广为所有病例—对照推断都适用。

每个实际分析结果有图任务或明确的配图缺口。复用规范配图关系，核对单位/粒度/配对/检验来源；适配转换若需要汇总，由分析计划显式定义并记录，不能借bindings隐式统计。方法—模板联调运行证据先留课题；只有适用范围已核查且作者审阅后，才按原规则更新正式关系验证。

图注说明对象、单位、分组、统计/摘要来源、探索或验证角色和限制。模板没有相应能力时省略不适用标注并说明，不能补造p值、用来源图冒充运行图，或为出图改写结果。

“精美”落实为能检查的图质量：优先复用已确认图样的原生配色/几何/主题；依据实际类别数、标签长度和数据密度按现有尺寸契约适配，检查文字/图例不截断、不遮挡，数值与单位正确，导出满足已确认用途。最终给出图文件、简要解释及必要限制；状态/日志由agent后台维护，作者不需手工拼接流程。
