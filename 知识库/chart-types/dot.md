# dot

## 回答什么问题

它要支持的论点是：各组的分类构成并不相同，某一类在特定组中的份额更高或更低。图把 group × category 的份额矩阵排开，让读者逐格比较每一类在各组中的占比，而不是判断总量或连续分布。因此它适合回答“谁以什么为主、构成如何随组变化”，不适合回答“哪组更多”或“分布是否不同”。

## 什么时候选它

适用于一个观测一行、带 group 与 category 两个分类标签（本库模板只读观测级 metadata；已有聚合比例表时需先展开为观测级标签，或改用 ring/stacked-bar-flow）的数据，组内份额之和默认为 1（percent 行为，可覆盖 `stat_type`），组数中等、类别数少（模板示例为 5 组 × 3 类、1000 个细胞）。当比较重点是每一类在各组中的占比，而不是单个组的整体饼形，或堆叠柱的中间段难以对齐比较时，优先选它；各组样本量不同但指标本身是比例时也适用。

## 什么时候不要用

需要表达绝对计数、组间总量差异或必须连同 n 解读时不要单独用它：组内百分比会隐去各组样本量，小样本组的份额本身不稳定，面积相同的点可能来自差别很大的观测数。组或类别很多、标签很长时会拥挤，模板宁可要求更大画布也不缩字；只有一两组时 pie/ring 更直接，组按时间或剂量有序且强调整体构成渐变时用 stacked-bar-flow/area。它不提供置信区间或组间检验，不能把构成差异当作统计证据。

## 与相近图型怎么区分

最容易与 dotplot 混：两者都是矩阵点图，但 dot 的面积编码组内构成比、颜色只重复行类别，dotplot 的颜色编码平均表达量、面积编码阳性比例，颜色是定量刻度。与 pie/ring/rose 相比，后三者靠扇区角度或半径表达各组构成、跨组比较要读不同环或花瓣，dot 把同一类别对齐成一行，适合逐类跨组比较；与 stacked-bar-flow/area 相比，流带或面积保留整体构成但中间层难读，dot 以整体感换取逐格可读；与 bar 相比，bar 从零起长度更利于绝对量比较。与 beeswarm/density-scatter（以及 boxplot/violin）相比，后者的每个点是一个观测或展示连续分布，dot 的每个点是一个聚合比例，不能反推样本分布或样本量。

## 常见误用

首要风险是把点面积读成绝对数量，或把每个点当成一个细胞/样本：它其实是组内百分比，组 n 不同则同一面积含义不同，图注应给出每组 n 或同时提供计数。面积判断精确值不如长度可靠，点大小图例不能省，0 与缺失在点阵里也都不显眼，需说明零值和 NA 的处理。类别多时颜色只是分类编码、与行位置冗余，不要用颜色暗示显著性并应选色盲安全配色，过密时拆图或改 bar 而不是缩字硬塞；图只展示构成，不能替代比例差异检验，也不应把份额变化写成因果。
