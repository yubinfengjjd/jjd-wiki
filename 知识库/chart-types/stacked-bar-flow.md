# stacked-bar-flow

## 回答什么问题

回答的是若干有序分组之间构成如何移动：各分类的份额在条件、样本或时间点之间如何此消彼长。它服务于描述性比较，即指出哪些类别的构成变化最明显，而不是证明组间差异显著、推断个体状态转移或给出因果解释。

## 什么时候选它

当有约 2–6 个可排序分组、每个分组内类别份额可归一化到 1、类别约 3–9 个，且目标是描述构成变化时选它；每个分组应有足够细胞或观测数，并在图注给出 n。分组或类别更多、分组本身无序，或需要精确读取每个 group × category 数值时，改用 dot（本库已有组成点阵），或用本模板把 `flow_alpha` 设为 0 近似无流带的 100% 堆叠柱；普通 bar/heatmap 不是本库可直接套用的组成模板。

## 什么时候不要用

分组不可排序、组数过多或类别过密时不要用，流带会把相邻柱连成并不存在的连续过程。存在缺组，或目标是组间统计检验、个体层面轨迹/状态转移推断时也不要用。模板默认 `normalize: true`，会在组内按 proportion 之和再归一化；输入未预先归一化也会被重算，但分析阶段仍应确认每组非负、可加并记录归一化方式。每组样本量很小时不要用它下结论，微小份额差异会被流带放大成视觉趋势。

## 与相近图型怎么区分

与 bar 的关键差别是多了流带；本库 bar 只有 SHAP 汇总模板，不是组成计数模板，流带只是相邻堆叠柱的线性视觉插值，不增加数值信息。trend 同样是堆叠柱加连接带，但保留计数尺度；stacked-bar-flow 把每组归一化到 1，只看构成并隐藏总量，area 则用连续填充带表示构成随有序 x 的变化、没有离散柱间隔。pie 与 ring 用角度展示单一或少数总体的构成，跨组比较角度困难且没有顺序轴；需要精确读取每个 group × category 数值时用 dot（组成点阵）或直接查表；heatmap 本库暂无模板。

## 常见误用

最常被误读的是把流带当成细胞轨迹、状态转移概率或因果变化——它只是相邻柱之间的直线插值，中间位置没有数据。按组归一化会掩盖各组总细胞数的差异，应同时报告每组 n；以细胞为重复单元做组间比较会构成伪重复，比例数据还有和为一的组成约束，推断需在样本层面并用组成数据分析方法。类别与堆叠顺序要在各组间固定并配图例，类别过多时需检查色盲可读性；该图不提供置信区间或检验，不能据图宣称组间差异显著。
