# ring

## 回答什么问题

回答的是“每个分组内部的类别构成是什么样、各组构成是否相似”，即组内 part-to-whole 的结构描述。它支撑构成描述与组间构成的定性对照，不支撑“哪类更多/更大”的定量排序，也不支撑差异显著性。

## 什么时候选它

数据是 group × category × proportion 的长表、每个组内比例和为 1（或可先由计数归一化），且分组数在个位数（理想 2–5 环；库内 layout 提示 >10 环会拥挤）、类别数约 3–6 个时选它。它最适合“各组混合构成是否相似、哪类在各组占主导”的描述，而不是跨组比大小。本库 ring 模板直接消费已归一化的比例表（render-cell-proportions：group, celltype, proportion），不需要细胞级明细；只有细胞级标签时 pie/rose 模板更省事。

## 什么时候不要用

需要精确读数或比较组间份额差异时不要用：角度/面积判断精度低，几个到十几个百分点的差别肉眼不可靠，改用 stacked-bar-flow 或堆叠柱。不要用环表示各组样本量或总量——比例归一化会隐藏组间 N 的差异，小 N 组的份额不稳定，容易被读成真实构成差异。组数/类别数多、标签长、0% 扇区多时也不要硬画：模板会因尺寸上限停止或出现扇区标签重叠；更不要把环序当时间/轨迹、把颜色当定量刻度。

## 与相近图型怎么区分

与 pie 的差别：pie 与 ring 都能画多个离散分组；pie 默认不留环间距、不加扇区标签，ring 用间距和标签强调逐组构成对照，并合并 0%/100% 端点标签。与 rose 的差别是 rose 以半径编码每类量值、角度只定位类别，适合比大小，ring 以角度编码组内份额；与 radial-bar 的差别是后者每条径向条表示一个特征的贡献大小（如 SHAP），不是组内构成。与 stacked-bar-flow 的差别是后者用 100% 堆叠柱加相邻组流带，读数更准、更适合看组间构成变化，ring 更紧凑但精度更低。

## 常见误用

最常见的审稿风险是把环当精确图：小扇区（约 <5%）之间以及 0% 与 100% 端点标签会重叠或叠在顶部，本库模板对极小扇区仍会标注、不自动省略，投稿前要逐图检查。其次是把归一化比例当成样本量证据：各组 N 不同或 N 很小时，比例差异可能只是抽样波动，环图本身不做检验，不能写成组间组成有差异。类别多时还要避免彩虹配色与色盲不可读，环序/颜色只作分类标识；不要用 3D、炸开扇区或半径夸大，中心空洞没有数值含义。
