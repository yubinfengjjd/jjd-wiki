# bar

## 回答什么问题

回答离散类别在某一连续度量上的大小与排序问题，例如哪些类别的计数、比例、均值或重要性更高。论证目标是支持类别间的主效应比较，而不是展示分布、趋势或因果。

## 什么时候选它

数据是“一个离散类别 + 一个汇总值”、类别数少到中等（以标签不重叠为准）且标签可读时选它；长标签或多类别优先横向条形并按数值排序。样本量不限制画图，但组间推断需要每类足够的原始观测和可解释的不确定性，不能只给均值。本库现有两个 bar 模板：历史“SHAP 条形图（含环形 inset）”只覆盖“每特征一条平均绝对 SHAP + 占比”的横向排序条形，固定 4.8×3.5 in、特征标签随 count 缩字号，任意 n 或长标签需另做可读性检查；新的“分组计数柱图”覆盖普通分类计数的 stack/dodge 柱图，读取逐细胞元数据、支持 count/percent、标签与 adaptive sizing。多系列误差棒或带统计标注的柱图仍没有现成模板，需按通用规则另写实现。

## 什么时候不要用

不要用它展示分布、个体值或小样本组间差异：均值柱会掩盖离散度、离群值和每组 n，容易把不稳定差异画成确定差异。不要用截断的数值轴、双 y 轴、3D 柱或跨组比较堆叠段，这些都会夸大或扭曲长度编码。类别过多、标签不可读，或 x 轴是连续时间/剂量时，改用点图、热图、箱线/小提琴，或按有序组画 trend（堆叠柱+面积连接）；连续变量分箱的频数分布用直方图/密度图，而不是把分箱当无序类别。

## 与相近图型怎么区分

与 stacked-bar-flow 相比，后者用堆叠段表达组内构成（总高归一到 100%，段间基线不同，流带只是视觉插值），area 是 group×stat 的 100% 堆叠面积（x 为分类组），有序组的堆叠柱+面积连接用 trend，bar 则是每类一个独立长度、比较同一度量的绝对大小。与 radial-bar 相比，后者把条形卷到极坐标、用半径编码数值，适合紧凑或环形版式，但共同基线和长度比较不如直线条形直观；pie、ring 用角度编码组内比例，rose 用花瓣半径/面积编码计数或比例，类别多时都难以精确比较，bar 保留共同零基线、可直接比较绝对量。与 boxplot、violin、density-scatter、beeswarm 相比，bar 只给一个汇总值：boxplot 给中位数/IQR/离群，violin 给密度形状，density-scatter 给配对散点与边缘分布，beeswarm 给逐样本带符号分布和特征值高低；小样本、偏态或需要方向时先逐点展示（strip/dot）并标 n；只有每组观测足以支撑四分位或核密度时才用箱线/小提琴。

## 常见误用

最常见的审稿风险是小样本均值柱：每类 n 很小或分布偏斜时，柱高与 SD/SE 会掩盖个体值和离群点，误差棒含义（SD/SE/CI）及 n 必须写进图注，也不能用误差棒重叠判断显著性；按点估计排序却不给不确定性，还会把不稳定的顺序画成确定排名。第二类是长度编码被扭曲：数值轴（纵向柱的 y 轴或横向条的 x 轴）不从 0 开始、使用对数轴、双 y 轴、3D/阴影，或跨组比较堆叠段，都会让读者按长度读出错的大小；类别过多时优先横向条形并增加高度，仍拥挤就改用点图或热图，并用色盲安全配色加标签/形状冗余编码。就本库 SHAP 模板而言，条形是平均绝对 SHAP，只表达重要性大小、不表达方向，也不能作因果解释；环形 inset 的半径按条数等距生成、不编码贡献值，percent 的分母是筛选前全部特征（筛选后合计可小于 100%），示例数值又是不确定转录，且 x 轴 0 在右端、条形向左延伸，这些都必须在图注或正文说明，不能当真实样本量或定量证据。
